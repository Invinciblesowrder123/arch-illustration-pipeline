## 二、需要您提供的资料

### 2.1 二十组历史绘图需求（最重要的一项）

请回想或翻找 20 个**真实提过或典型**的绘图需求，并为每组写出"期望命中的文献和页码"。
格式随意，能对上就行：

| # | 绘图需求（一句话） | 期望命中的文献 | 期望页码（可留空） |
|---|---|---|---|
| 1 | 绘制二里头文化绿松石龙形器的科学复原图（俯视 45°，白描线图） | 《二里头 1999—2006》发掘报告 | p.XXX |
| 2 |  |  |  |
| 3 |  |  |  |

**为什么用这个格式**：系统会拿这 20 组去自动跑检索，统计命中率与前几名命中明细。
以后凡是动检索、切片、阈值，都先跑它——**它是防止我们"越调越差"的唯一护栏**。
页码填不出来就留空，只填文献名也能用。

## 三、需要您拍板的选择

### 3.1 图内标注：两种方式二选一

| | **A. caption_only（当前默认）** | **B. in_image** |
|---|---|---|
| 图内长什么样 | **图内不出现任何文字**，只用细引线指出标注位置 | 标注文字**写在图上**，强制简体中文 |
| 名称放哪 | **图下图注表**：编号 ｜ 名称 ｜ 图上位置（报告里自动生成，正文可直接用） | 图内 |
| 学术惯例 | 考古线图最常见的做法（图内标号、图版说明给名称） | 图版中也常见，但依赖模型把中文写对 |
| 风险 | 需正文配图注表 | 文生图模型渲染中文**不稳定**：可能出现伪汉字、缺笔，校验会把这类判为不通过并要求重画 |
| 校验规则 | 图内出现任何文字、字母、数字即不通过 | 出现英文、乱码、不可辨即不通过 |

**建议**：由我们各出一版样图（同一需求、同一知识），您对比后勾一个。
若选 A 又想在图面上看到编号数字，请一并说明——**默认 A 是连数字也不出现的**
（图注表用"图上位置"这一列来描述引线指向哪儿）。

### 3.2 服务器内存（这一项已经基本有答案了）

早先的实测结论是：嵌入模型 `BAAI/bge-m3` 会独占 **17.1GB** 内存，整栈约 20.5GB，
看上去必须换更省内存的嵌入模型、或上 ≥32GB 的服务器。

**2026-09-24 复查后更正**：那 17GB **不是模型本身，而是嵌入服务的并发缓冲区**
（默认允许 512 个并发请求、每批 16384 token）。给它加上并发上限之后：

| | 默认参数 | 加上限后 |
|---|---|---|
| 嵌入服务常驻内存 | 17.1 GB | **4.98 GB** |
| 整个服务栈 | 约 20.5 GB | 约 8.2 GB |
| 入库速度 | 3–5 页/分钟（还容易因内存不足被系统杀掉） | 4.2–6.5 页/分钟 |

**结论：16GB 内存的服务器就能跑，既不必换更小的嵌入模型，也不必非要 32GB。**
（换模型会让已入库的向量全部作废重算，所以这个更正很关键。）

只差确认一件事：目标服务器实际内存是多少？

### 3.3 入库排期

215 篇真实语料的全量入库占机器时间较长（实测：论文 3–5 页/分钟，扫描专著约 2.3 页/分钟）。

## 四、拉下项目后怎么跑

### 4.1 拉取（PowerShell）

```powershell
git clone https://github.com/Invinciblesowrder123/arch-illustration-pipeline.git
cd arch-illustration-pipeline
pip install -r requirements.txt
```

- 默认拿到的就是最新主线（含本清单）。已克隆过则 `git pull` 即可。
- 右边栏 **Releases** 页有 v1.1.0 的发布说明（这一版改了什么、怎么用）。
- 若本机没装 git：在仓库页面点 `Code` → `Download ZIP`，解压同样可用。

### 4.2 填密钥

密钥由我们这边单独提供（仓库里只有 `.env.example` 占位，不含任何真实密钥）。
把 `.env.example` 复制为 `.env`，填三处：语言模型 Key、绘图 Key、视觉校验 Key（默认复用语言模型）。

### 4.3 三条命令

```powershell
python main.py --check --skip-image
python main.py --mode rag
python main.py --revise output/run_xxxx --feedback "您的意见"
```

第一条是自检（连通性 + 环境指纹，零绘图费用）；第二条正式出图（默认最多 3 轮自动重绘）；
第三条是看图之后按意见重绘（见 §5）。

### 4.4 产物在哪、看什么

| 路径 | 看什么 |
|---|---|
| `output/run_时间戳/report.md` | **主报告**：知识来源与检索词、引用文献（含页码）、图注表、每轮问题清单与评分 |
| `output/run_时间戳/illustration_attempt_N.png` | 各轮尝试图（最后一张不一定通过） |
| `output/run_时间戳/final_illustration.png` | 通过校验的成品（没有这个文件 = 没通过） |
| `knowledge/knowledge_summary.md` | AI 汇总的绘图知识——**请重点核对**：条目是否忠实于文献、页码是否对得上 |

## 五、看图提意见怎么写

这一版的意义就在这儿：**您不必改需求从头再来**。写一段话即可，系统会
①拆成若干条 → ②逐条改 → ③**逐条回执**（改了没有 + 证据在图面哪个位置）。

写法就三件事：

1. **哪一处不对**——尽量指到图面位置（"画面下方居中"比"整体"有用）
2. **应该是什么**——要具体、可判定
3. **哪些地方不许动**——没说的我们也会默认不动，但您明说更稳

**好的示例**

```text
1. 图内标注不要英文，改成中文，写在图外图注表里也行；
2. 底部那根比例尺移到右下角，不要压在器物下方；
3. 镶嵌片的边界不要画得太规则，现在像砖墙；
4. 构图、视角、器物形制不要改。
```

**无效的示例**（无法判定，系统只能整段照抄，效果差）

```text
整体还不够准确，再优化一下，风格再学术一点。
```

一次 2–6 条最佳，每条一行。
